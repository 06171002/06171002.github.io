## 직거래는 상품이 아니라 '관계'의 속성이다

운영 중이던 대행 트랙 위에, 구매기업이 공급사와 직접 거래하는 트랙을 얹었다. 새로 만드는 일이 아니라 돌아가는 파이프라인을 고치는 일이었다. 운영사가 거래 당사자에서 빠지므로 판정 → 장바구니 → 주문 → 정산 → 클레임 → 통계까지 모든 계층에서 운영사를 걷어내야 했다.\
같은 상품이라도 A기업에겐 직거래, B기업에겐 대행이다. 개발 데이터에서도 한 품목이 1개 기업에는 고객사 소유, 51개 기업에는 운영사 소유였다. 상품에 플래그 하나로는 표현할 수 없어서 **표준품목의 소유자 × 그 고객사와의 연결**, 두 축으로 판정한다.

<figure class="diagram"><img src="/content-assets/b2b/direct-trade/diagram-1.light.svg" alt="직거래는 상품이 아니라 '관계'의 속성이다 다이어그램" class="diagram-light" loading="lazy" decoding="async"><img src="/content-assets/b2b/direct-trade/diagram-1.dark.svg" alt="직거래는 상품이 아니라 '관계'의 속성이다 다이어그램" class="diagram-dark" loading="lazy" decoding="async"></figure>

- <strong>판정은 세 값이다.</strong> 고객사 소유인데 연결이 없을 때 '일단 대행'으로 넘기면, 운영사가 당사자가 아닌 거래를 자기 매출로 떠안는다. 그래서 대행으로 넘기지 않고 **차단**한다.
- 자격이 서려면 조건 6개가 모두 참이어야 한다 — 고객사 소유 · 나의 연결 있음 · 소유 행 사용 중 · 소유 행 삭제 안 됨 · 연결 사용 중 · 연결 삭제 안 됨(그리고 표준품목이 살아 있을 것). 하나만 빠져도 판정이 뒤집혀, 남의 고객사 소유로 내 상품이 자동승인되거나 끊은 직거래로 자동승인이 계속된다. 그래서 조건별로 쪼개 각각 테스트로 고정했다.
- 판정 축은 조인이 깊어 목록에서 N+1 이 될 수 있어, 목록 판정을 쿼리 1회로 고정하고 테스트로 잠갔다.

| **고르지 않은 판정 축** | **이유**                                  |
| --------------- | --------------------------------------- |
| 상품에 직거래 여부 컬럼   | 같은 상품이 기업마다 다른 트랙이라 표현할 수 없다            |
| 공급사 단위 플래그      | 같은 공급사도 품목마다 소유자가 갈린다                   |

</div>

## 한 주문에 두 트랙을 섞지 않는다

결제 수단 · 정산 주체 · 격리 범위가 모두 주문(SO) 단위다. 대행 라인과 직거래 라인이 한 주문에 섞이면 셋 다 정의할 수 없어서, 장바구니에서 고를 때 한 번 막고 주문을 만들 때 다시 판정한다(혼합도, 차단 단독도 거부). 그리고 주문 헤더에 **직거래 여부 스냅샷**을 박아, 그 뒤의 격리 판정은 매번 조인으로 역산하지 않고 이 값을 정본으로 쓴다.

<figure class="diagram"><img src="/content-assets/b2b/direct-trade/diagram-2.light.svg" alt="한 주문에 두 트랙을 섞지 않는다 다이어그램" class="diagram-light" loading="lazy" decoding="async"><img src="/content-assets/b2b/direct-trade/diagram-2.dark.svg" alt="한 주문에 두 트랙을 섞지 않는다 다이어그램" class="diagram-dark" loading="lazy" decoding="async"></figure>

혼합이 금지돼 있으니 헤더 값 하나로 라인 전체가 직거래임이 보장된다. 클레임 병합 집계도 주문 헤더를 조인해 트랙을 판정한다 — 라인 축으로는 판정하지 않는다.

## 운영사는 없다 — 격리는 필터가 아니라 부재로

운영사는 당사자가 아니므로 <strong>직거래 전용 관리자 API 를 하나도 만들지 않았다.</strong> 대신 기존 관리자 진입점마다 배제 필터를 실었다. 진입점은 수십 곳이고 계속 늘어나서, 하나만 새도 운영사가 당사자 아닌 거래를 보게 된다.

<figure class="diagram"><img src="/content-assets/b2b/direct-trade/diagram-3.light.svg" alt="운영사는 없다 — 격리는 필터가 아니라 부재로 다이어그램" class="diagram-light" loading="lazy" decoding="async"><img src="/content-assets/b2b/direct-trade/diagram-3.dark.svg" alt="운영사는 없다 — 격리는 필터가 아니라 부재로 다이어그램" class="diagram-dark" loading="lazy" decoding="async"></figure>

상세 화면은 직거래 라인이 섞이면 403 이 아니라 **404** 를 돌려준다. 거부가 아니라 존재 자체를 누설하지 않기 위해서다.

## 돈의 축 — 청구는 라인 합계, 환원은 직거래 원장으로

직거래에는 운영사 마진이 없으므로 **공급사 청구액 = 구매사 결제액**이어야 한다. 공급가를 개당 단가 × 수량으로 되짚으면 나누어떨어지지 않을 때 1원이 남고, 전량 취소해도 청구액이 0이 되지 않는다.

<figure class="diagram"><img src="/content-assets/b2b/direct-trade/diagram-4.light.svg" alt="돈의 축 — 청구는 라인 합계, 환원은 직거래 원장으로 다이어그램" class="diagram-light" loading="lazy" decoding="async"><img src="/content-assets/b2b/direct-trade/diagram-4.dark.svg" alt="돈의 축 — 청구는 라인 합계, 환원은 직거래 원장으로 다이어그램" class="diagram-dark" loading="lazy" decoding="async"></figure>

- 이 계산은 SQL 안에 직거래 여부 게이트를 두어 대행 주문에는 닿지 않는다(fail-closed).
- 직거래 클레임이 끝나면 PG 를 부르지 않고 **예산 원장에 음수 행**을 넣어 되돌린다. 원 사용 행의 배분 정보 · 결제수단 · 참조번호를 그대로 복사하고, 순잔액을 상한으로 복원한다(원 차감액을 넘지 못한다 · 순잔액이 0이면 넣지 않는다). 직거래 차감분이 아닌 원장 행은 되돌리지 않는다 — 여신 원장을 잘못 복원하지 않게. 부분 취소를 여러 번 해도 회차 합계가 원 차감액을 넘지 않는다.

## 연결 · 초대

<figure class="diagram"><img src="/content-assets/b2b/direct-trade/diagram-5.light.svg" alt="연결 · 초대 다이어그램" class="diagram-light" loading="lazy" decoding="async"><img src="/content-assets/b2b/direct-trade/diagram-5.dark.svg" alt="연결 · 초대 다이어그램" class="diagram-dark" loading="lazy" decoding="async"></figure>

- 해제는 행을 지우지 않고 사용 여부만 끈다(다른 출처 행은 그대로). 재연결은 해제된 행을 다시 켠다 — 새 행을 만들지 않는다. 승인할 때 수동 등록 행이 이미 있으면 출처를 직거래로 승격한다.
- **링크 유출 방어** — 초대 토큰은 초대받은 이메일 계정으로만 수락할 수 있다(대소문자 무시). 다른 계정 · 자사 발송분은 거절하고, 만료된 토큰은 상태 · 토큰을 바꾸지 않고 400.
- 연결은 모기업 단위라 종사업장 계정의 요청 · 수락은 모두 막는다.
- 초대받은 공급사가 가입하면 바로 승인되는 경로는 「기업회원요청관리」 카드에 있다.
